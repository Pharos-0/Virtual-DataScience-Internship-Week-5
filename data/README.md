IBM's documentation for its Telco customer churn sample describes the data as
belonging to a *fictional* telco company and states that the churn column
indicates whether the customer departed within the last month
(https://www.ibm.com/docs/en/cognos-analytics/12.0.x?topic=samples-telco-customer-churn).
The repository itself does not include a formal data dictionary, so the
descriptions below are based on the column names and the values observed in the file.

The raw file is redistributed here unchanged under the terms of the Apache 2.0
licence, with the licence text included. `src/01_data_acquisition.py`
re-downloads it if it is missing and checks the SHA-256 value above.
`data/processed/telco_churn_clean.csv` is regenerated by `src/02_data_cleaning.py`
(SHA-256 `ec3ef03fbe050a90c06893621f92720beaa3136176ef5e91e1b5fc4d40164fec`),
and every later stage verifies this checksum when it loads the file.

## Cleaning applied (summary)

- `TotalCharges` was stored as text because 11 rows contained a single space.
  All 11 rows have `tenure = 0`, so the value was set to 0 (no completed billing month).
- `SeniorCitizen` 0/1 recoded to No/Yes to match the other yes/no columns.
- Text columns converted to pandas `category`; `churn_flag` added.
- No rows removed: there are no duplicate records and no impossible values.

## Known limitations

- The data describes a fictional company (per IBM) and is a single snapshot:
  there is no date for when each customer joined or left.
- The churn observation window is described by IBM as "the last month"; the
  CSV itself contains no date fields to confirm this.
- `MonthlyCharges` is the current price, so it does not show price changes over
  a customer's lifetime.
