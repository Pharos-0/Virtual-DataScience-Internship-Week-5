# Virtual DataScience Internship - Week 5

## Final Project: Customer Churn Analysis and Strategic Recommendations

Week 5 (final project) of the Virtual Data Science with Python Apprentice Internship.
This repository brings the five-week project together into one reproducible,
end-to-end analysis of customer churn: acquisition and cleaning, exploratory
analysis, visual storytelling, hypothesis testing, a predictive model, and
evidence-based strategic recommendations.

## Dataset

**IBM Telco Customer Churn**: 7,043 customers x 21 columns of a telecom provider that IBM describes
as fictional. Source: [IBM/telco-customer-churn-on-icp4d](https://github.com/IBM/telco-customer-churn-on-icp4d)
(Apache License 2.0; the raw file and licence are in `data/raw/`). The target is `Churn`
(26.54% churned). See [`data/README.md`](data/README.md).

## Key findings

- **Contract type** is the strongest and most consistent driver: churn is 42.7% for month-to-month,
  11.3% for one-year and 2.8% for two-year contracts. Cramer's V = 0.41, and the tenure-adjusted
  odds ratio is 7.11 (95% CI 5.87-8.61).
- **Early tenure**: 55.5% of churners left within their first 12 months.
- **Fibre optic** customers churn at 41.9% (DSL 19.0%). Within each internet service churners pay
  *less*, so price alone does not explain churn.
- Internet customers **without online security or tech support** churn at about 42%, against about 15%
  for those with them.
- The **logistic regression** reaches a test ROC-AUC of 0.848. Ranking customers by predicted risk,
  the top 20% contain 51.3% of churners.
- Churned customers accounted for 30.5% of total monthly charges.

All findings are associations in observational data. None establishes cause and effect.

## Strategic recommendations (summary)

1. Early-life retention programme for new month-to-month customers, tested against a control group.
2. Randomised test of incentives to move month-to-month customers to one-year contracts.
3. Model-based, tiered prioritisation of retention outreach.
4. Investigate the fibre optic customer experience before changing prices.
5. Pilot security and tech-support trials for internet customers without them.
6. Lower priority: test incentives for automatic payment.

## How to reproduce

Tested with Python 3.11.9 (pandas 3.0.6, NumPy 2.4.6, Matplotlib 3.11.2, Seaborn 0.13.2, Plotly
7.1.0, SciPy 1.17.1, statsmodels 0.15.0, scikit-learn 1.9.1).

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python src/run_all.py                # runs stages 01-07 in order (about 20 seconds)
python notebooks/build_notebook.py   # optional: rebuild and execute the Week 5 notebook
```

A single seed (`RANDOM_SEED = 42`) controls the train/test split, the cross-validation folds, the
decision tree and the bootstrap. The raw and cleaned data are verified by SHA-256 checksums. A full
run reproduces the result files of the weekly repositories byte for byte.

## Notebook and screenshots

`notebooks/Week_5_Final_Project.ipynb` is built from `src/07_final_analysis.py` (Jupytext percent
format) and executed. It reads the outputs of stages 01-06, so run `src/run_all.py` first on a
fresh checkout. The images in `screenshots/` are crops of the executed notebook.

## Limitations

- IBM describes the data as a fictional company, captured in a single snapshot with no dates.
- Associations only: the recommendations are framed as tests to run, not proven effects.
- There are no cost, satisfaction, usage or service-quality data, so monetary impact cannot be
  estimated and the reasons for churn cannot be observed.

The written final report is submitted separately through the internship portal.
